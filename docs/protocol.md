# Pico355 wire protocol, seams and open TBDs

Not SSOT. The SysMLEdge desk `sysmledgeprj-rpipico-adxl355` @ `e364458f462c7b2153b6e6acd914b187e32b97fb`
is the source of truth; this file only fixes the code seams around it. Every value
marked TBD below is a "not configured" sentinel in code until the owner decides it
(rule in "TBD rule" below).

## TBD rule (one behaviour for every module)

| Kind | Firmware sentinel | Test | Rust mirror |
|---|---|---|---|
| numeric `CFG_*` (SPI clock/mode, FIFO watermark, default filter, overflow policy, every `CFG_PROTO_*`) | `CFG_TBD` = `0xFFFFFFFFFFFFFFFFull` | `CFG_IS_TBD(x)` (C and `#if`) | `Option<T>` = `None` (`tbd.rs`) |
| register address / bit field / code | `ADXL355_TBD` (same value, `adxl355_regs.h`), flag `ADXL355_REGS_ARE_TBD` | `ADXL355_IS_TBD(x)` | - |
| enum value | `ADXL355_RANGE_UNSET`, `FSM_STATE_UNSET`, `FSM_POLICY_UNSET`, `ADXL355_FILTER_UNSET` (-1) | `== *_UNSET` | `Option` (`config.rs`) |
| array size | placeholder `CFG_SAMPLE_BUFFER_DEPTH` 1 + flag `CFG_SAMPLE_BUFFER_DEPTH_IS_TBD` 1; placeholders `CFG_USB_FRAME_BUF_BYTES` / `CFG_USB_RX_BUF_BYTES` 64 + flag `CFG_USB_BUF_BYTES_IS_TBD` 1 | the flag | - |

1. No sentinel equals a legal value: every decided `CFG_*` or register value fits in 32 bits
   (8 bits for registers), the 64-bit all-ones sentinel does not; enum `*_UNSET` members are
   not states/ranges/policies; no legal filter code is negative.
2. Order in every function: argument check (`*_ERR_ARG`), then TBD check, then the work.
   A function that needs a TBD value returns its module's TBD code and has no side effect on
   hardware or output bytes (`*out_len`, `*consumed`, `*n_read`, `*pushed`, `*sent` set to 0):
   `ADXL355_ERR_TBD`, `ACQ_ERR_TBD`, `USB_STREAM_ERR_TBD`, `COMMAND_ERR_TBD`, `FSM_ERR_TBD`,
   `PROTOCOL_ERR_TBD`; Rust `ProtocolError::Tbd`, `LinkError::Tbd`.
3. A TBD code from a lower module propagates as the caller's TBD code (adxl355 -> acquisition,
   protocol -> usb_stream / command), never as a generic error.
4. A value is used only after its TBD test is false, through an explicit cast to the field
   width. An unchecked implicit use of `CFG_TBD` in a byte/32-bit field fails `-Werror`
   (`-Woverflow` / `-Wtype-limits`) on purpose.
5. Stub bodies (A1) return `*_ERR_NOT_IMPLEMENTED`; implementations never do.
6. Test injection: each `CFG_*` value in `config.h` is wrapped in `#ifndef`, so a host test
   target may compile a module with `-DCFG_PROTO_SYNC=<v>` etc. (test data only, never a
   design value). The fsm table is injected through `fsm_init` (below). Rust tests can only
   observe the `None` behaviour until values are decided.

## ADXL355 driver contract (register map from no-OS)

`firmware/include/adxl355_regs.h` is filled from the Analog Devices no-OS driver
(`drivers/accel/adxl355/adxl355.h` and `adxl355.c`, pinned to commit
`4557b1f58f8a233bd116dbb02d8d5c447d3699b6`; owner-named source). Every value carries a
`no-OS H:<line>` / `no-OS C:<line>` citation in the header. Entries the no-OS driver does not
define stay `ADXL355_TBD`: `ADXL355_FIFO_CAPACITY` (no-OS gives only the watermark maximum
`ADXL355_FIFO_SAMPLES_MAX` 0x60). `ADXL355_REGS_ARE_TBD` is computed from the entries the driver
uses: today 0. Contract (`adxl355.h` header comment), for `adxl355_init`, `_configure`,
`_set_measuring`, `_read_sample`, `_read_fifo`, `_status`:

1. `ADXL355_ERR_ARG` for NULL pointers, `bus->transfer` NULL, range not 2G/4G/8G, `odr_hz` not one of
   4000/2000/1000/500/250/125, filter not `ADXL355_FILTER_UNSET` or 0..`ADXL355_HPF_CODE_MAX`.
2. `ADXL355_ERR_TBD` if a register entry the operation needs is TBD: zero `transfer()`
   calls, `*out`/`*status` unchanged, `*n_read` = 0. `adxl355_init` still binds `dev->bus`,
   loads `dev->config` defaults and leaves `dev->initialised` false. The check is per operation.
3. `ADXL355_ERR_NOT_INIT` if init has not succeeded; 4. `ADXL355_ERR_BUS` / `ADXL355_ERR_ID`; 5. `ADXL355_OK`.

Sequences implemented from no-OS: init = soft reset (write reset code, poll STATUS until
NVM_BUSY clears, 255 tries) then DEVID_AD, DEVID_MST, PARTID check; configure = POWER_CTL to
standby if measuring, RANGE, ODR/LPF, HPF read-modify-write, restore POWER_CTL;
set_measuring = POWER_CTL write; read_sample = three 3-byte reads (X, Y, Z), 20-bit two's
complement in bits 23..4; read_fifo = FIFO_ENTRIES, then one FIFO_DATA burst of whole X/Y/Z
samples; status = STATUS read. Not taken from no-OS: the 1 ms delay and shadow-register compare
after reset (`adxl355_bus_t` has no delay hook). SPI command byte = (address << 1) | read bit
(no-OS C:46, C:81). SPI mode and clock are not defined by these files and stay TBD (`CFG_SPI_MODE`,
`CFG_SPI_CLOCK_HZ`). Host tests: `test_adxl355.c` (mock register file, cited IDs),
`test_adxl355_tbd.c` (all-TBD header generated by CMake), `test_adxl355_partial.c` (one entry TBD).

## State machine table supply

`fsm_init(fsm, table, len, initial, policy)` takes the transition table (not copied; must
outlive the fsm), its length, the initial state and the unknown-event policy, so host tests
inject a table. `fsm_init_default(fsm)` passes the TODO(TBD) defaults from `config.h`
(`CFG_FSM_TRANSITION_TABLE` rows, `CFG_FSM_INITIAL_STATE`, `CFG_FSM_UNKNOWN_EVENT_POLICY`);
`main.c` calls it, and it returns `FSM_ERR_TBD` while they are unset. Full rules in `fsm.h`.

## Link

USB CDC serial (proposed in the model, pending owner approval), one byte stream in each direction:

- Pico -> PC: sample-batch frames (sampleStream, PICO355-R5) and response frames (commandChannel, PICO355-R6).
- PC -> Pico: command frames (commandChannel, PICO355-R6).

## Frame layout (all TBD)

`firmware/src/protocol.c` is the only firmware owner of the layout; `hmi/src/protocol.rs` is its mirror.
The fields of a frame, in order, are named by these constants:

| Firmware (`config.h`) | Rust (`tbd.rs`) | Meaning | Value |
|---|---|---|---|
| `CFG_PROTO_SYNC` | `PROTO_SYNC` | sync byte at frame start | TBD |
| `CFG_PROTO_HEADER_LEN` | `PROTO_HEADER_LEN` | header length in bytes | TBD |
| `CFG_PROTO_LENGTH_FIELD_BYTES` | `PROTO_LENGTH_FIELD_BYTES` | width of the payload length field | TBD |
| `CFG_PROTO_CHECKSUM_KIND` | `PROTO_CHECKSUM_KIND` | checksum choice (none / sum / CRC) | TBD |
| `CFG_PROTO_MAX_PAYLOAD` | `PROTO_MAX_PAYLOAD` | maximum payload length | TBD |
| `CFG_PROTO_TYPE_SAMPLE_BATCH` | `PROTO_TYPE_SAMPLE_BATCH` | frame type id: sample batch | TBD |
| `CFG_PROTO_TYPE_COMMAND` | `PROTO_TYPE_COMMAND` | frame type id: command | TBD |
| `CFG_PROTO_TYPE_RESPONSE` | `PROTO_TYPE_RESPONSE` | frame type id: response | TBD |

Layout names (where each field sits and how it is encoded). Offsets are bytes from the start of
the header (header fields) or of the payload (payload fields); a `*_MSB_FIRST` value is 1 for most
significant byte first, 0 for least significant byte first; value and axis widths are 1..4 bytes:

| Firmware (`config.h`) | Rust (`tbd.rs`) | Meaning | Value |
|---|---|---|---|
| `CFG_PROTO_SYNC_OFFSET` | `PROTO_SYNC_OFFSET` | header offset of the sync byte | TBD |
| `CFG_PROTO_TYPE_OFFSET` | `PROTO_TYPE_OFFSET` | header offset of the frame type id byte | TBD |
| `CFG_PROTO_LENGTH_OFFSET` | `PROTO_LENGTH_OFFSET` | header offset of the payload length field | TBD |
| `CFG_PROTO_LENGTH_MSB_FIRST` | `PROTO_LENGTH_MSB_FIRST` | byte order of the length field | TBD |
| `CFG_PROTO_PAD_BYTE` | `PROTO_PAD_BYTE` | value of header/payload bytes no field covers (ignored on decode) | TBD |
| `CFG_PROTO_CHECKSUM_NONE` | `PROTO_CHECKSUM_NONE` | the `CFG_PROTO_CHECKSUM_KIND` code meaning "no checksum" | TBD |
| `CFG_PROTO_CMD_PAYLOAD_LEN` | `PROTO_CMD_PAYLOAD_LEN` | command payload length | TBD |
| `CFG_PROTO_CMD_CODE_OFFSET` | `PROTO_CMD_CODE_OFFSET` | payload offset of the command code byte | TBD |
| `CFG_PROTO_CMD_VALUE_OFFSET` | `PROTO_CMD_VALUE_OFFSET` | payload offset of the command value | TBD |
| `CFG_PROTO_CMD_VALUE_BYTES` | `PROTO_CMD_VALUE_BYTES` | width of the command value | TBD |
| `CFG_PROTO_RESP_PAYLOAD_LEN` | `PROTO_RESP_PAYLOAD_LEN` | response payload length | TBD |
| `CFG_PROTO_RESP_CODE_OFFSET` | `PROTO_RESP_CODE_OFFSET` | payload offset of the response code byte | TBD |
| `CFG_PROTO_RESP_CMD_CODE_OFFSET` | `PROTO_RESP_CMD_CODE_OFFSET` | payload offset of the answered command code byte | TBD |
| `CFG_PROTO_RESP_VALUE_OFFSET` | `PROTO_RESP_VALUE_OFFSET` | payload offset of the response value | TBD |
| `CFG_PROTO_RESP_VALUE_BYTES` | `PROTO_RESP_VALUE_BYTES` | width of the response value | TBD |
| `CFG_PROTO_VALUE_MSB_FIRST` | `PROTO_VALUE_MSB_FIRST` | byte order of the command/response value | TBD |
| `CFG_PROTO_SAMPLE_AXIS_BYTES` | `PROTO_SAMPLE_AXIS_BYTES` | bytes per axis value (two's complement, at least `ADXL355_SAMPLE_BITS` = 20 bits, model resolutionBits) | TBD |
| `CFG_PROTO_SAMPLE_MSB_FIRST` | `PROTO_SAMPLE_MSB_FIRST` | byte order of each axis value | TBD |

A frame, in these names:

- Header, `CFG_PROTO_HEADER_LEN` bytes: `CFG_PROTO_SYNC` at `CFG_PROTO_SYNC_OFFSET`; the type id
  (`CFG_PROTO_TYPE_*`) at `CFG_PROTO_TYPE_OFFSET`; the payload length at `CFG_PROTO_LENGTH_OFFSET`,
  `CFG_PROTO_LENGTH_FIELD_BYTES` wide, order `CFG_PROTO_LENGTH_MSB_FIRST`; every other header byte
  is `CFG_PROTO_PAD_BYTE`.
- Payload: right after the header, at most `CFG_PROTO_MAX_PAYLOAD` bytes; bytes no field covers are
  `CFG_PROTO_PAD_BYTE`.
- Checksum: only `CFG_PROTO_CHECKSUM_KIND == CFG_PROTO_CHECKSUM_NONE` is implemented; any other kind
  returns `PROTOCOL_ERR_NOT_IMPLEMENTED` (no checksum algorithm is decided).
- Command payload (`protocol_command_t` / `protocol::Command`), `CFG_PROTO_CMD_PAYLOAD_LEN` bytes:
  `code` at `CFG_PROTO_CMD_CODE_OFFSET`, `value` at `CFG_PROTO_CMD_VALUE_OFFSET`
  (`CFG_PROTO_CMD_VALUE_BYTES`, order `CFG_PROTO_VALUE_MSB_FIRST`).
- Response payload (`protocol_response_t` / `protocol::Response`), `CFG_PROTO_RESP_PAYLOAD_LEN` bytes:
  `code`, `cmd_code` and `value` at the `CFG_PROTO_RESP_*` offsets (`value`
  `CFG_PROTO_RESP_VALUE_BYTES` wide, order `CFG_PROTO_VALUE_MSB_FIRST`).
- Sample-batch payload: N samples of the model AccelSample axes `x, y, z` in that order, each
  `CFG_PROTO_SAMPLE_AXIS_BYTES` two's complement, order `CFG_PROTO_SAMPLE_MSB_FIRST`; N is bounded by
  `CFG_PROTO_MAX_PAYLOAD` (batch size also depends on the FIFO watermark, TBD).

`firmware/src/protocol.c` reads only these names. It returns `PROTOCOL_ERR_TBD` (no byte written,
`*out_len` / `*consumed` 0) while any name a function needs is TBD, and also when the values do not
form a consistent layout (overlapping fields, a field outside its header or payload, a width outside
1..4, a flag other than 0/1, an axis narrower than `ADXL355_SAMPLE_BITS`). A command/response value
or sample axis that does not fit its decided width returns `PROTOCOL_ERR_TOO_LONG`.
`hmi/src/protocol.rs` mirrors the names but has no codec yet, so it returns `Tbd` even when all are decided.

## Open TBD list (ten)

1. SPI clock - `CFG_SPI_CLOCK_HZ` (firmware does not initialise SPI0 while TBD).
2. SPI mode - `CFG_SPI_MODE`.
3. FIFO watermark - `CFG_FIFO_WATERMARK`.
4. Sample buffer depth and overflow policy - `CFG_SAMPLE_BUFFER_DEPTH` (placeholder 1, flag `CFG_SAMPLE_BUFFER_DEPTH_IS_TBD`; full after one push), `CFG_SAMPLE_BUFFER_OVERFLOW_POLICY` (while TBD a push on full stores nothing, counts an overflow, returns `SAMPLE_BUFFER_OVERFLOW`).
5. USB frame format and frame layout - `CFG_PROTO_*` tables above (field values, offsets, widths, byte order, pad byte, checksum-none code, command/response/sample encoding); USB scratch sizes `CFG_USB_FRAME_BUF_BYTES`, `CFG_USB_RX_BUF_BYTES` (placeholder 64, flag `CFG_USB_BUF_BYTES_IS_TBD`).
6. Command set - `CFG_PROTO_CMD_*` / `CFG_PROTO_RESP_*` above.
7. State transition details - `CFG_FSM_INITIAL_STATE`, `CFG_FSM_TRANSITION_TABLE`, `CFG_FSM_UNKNOWN_EVENT_POLICY` (PICO355-R7).
8. LDO output check - TPS7A2033 output voltage not yet checked against its datasheet (PICO355-R3); hardware, no code constant.
9. Cable pinout - X5 cable assumed straight 1:1, unverified; hardware, no code constant.
10. HMI form - GUI or CLI; placeholder is a plain terminal text view (`tbd::HMI_FORM`). Related HMI TBDs: log format, serial settings, port discovery, refresh rate (`tbd.rs`).

Also open from the ADXL355 driver (not defined by the no-OS files): `ADXL355_FIFO_CAPACITY`, the
post-reset delay and shadow-register compare. Default range and filter settings exposed are TBD
in the model.

## Confirmed constants

- Pins (model X5Port): GP16 SPI0 RX/MISO, GP17 CSN, GP18 SCK, GP19 TX/MOSI, GP22 DRDY input (never driven); INT1/INT2 unconnected.
- Default ODR 4000 Hz (PICO355-R1): `CFG_DEFAULT_ODR_HZ`, `config::DEFAULT_ODR_HZ`.
